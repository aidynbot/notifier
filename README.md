# GovTech: сервис уведомлений для бизнеса

Демо-сервис для подготовки и доставки процессуальных уведомлений субъектам предпринимательства. MVP показывает работу специалиста государственного органа и демонстрационного личного кабинета бизнеса в сценарии, похожем на eGov Business.

> Это демонстрационный проект: кабинет бизнеса и интеграции могут работать в тестовом режиме. SMS отправляются через выбранный внешний SMS-шлюз; интеграция с 1414 в MVP не используется.

Подробные согласованные роли, правила выбора статей и вложений, а также сценарий создания и отправки описаны в [требованиях MVP](MVP_REQUIREMENTS.md).

## Цель MVP

Показать основной сценарий: специалист создаёт уведомление, проверяет его в предпросмотре, при необходимости возвращается к заполненной форме для редактирования и отправляет его. Система передаёт уведомление в демо-кабинет бизнеса, отправляет SMS через внешний шлюз и фиксирует доставку и прочтение.

## Функциональность MVP

- Создание уведомления с данными бизнеса, одной или несколькими статьями, датой, временем и адресом явки.
- Хранение статей и шаблонов в справочнике; ручной ввод реквизитов и текста для отсутствующих статей или шаблонов с последующим просмотром администратором.
- Автоматические обязательные слоты для акта о назначении проверки и проверочного листа, если хотя бы одна выбранная статья требует эти файлы.
- Индивидуальный адрес по умолчанию для специалиста с возможностью изменить его для уведомления и отдельно сохранить новое значение по умолчанию.
- Предпросмотр уведомления, возврат к заполненной форме для редактирования и отправка из предпросмотра.
- Демо-кабинет бизнеса со статусами `DELIVERED` и `READ`.
- Отправка SMS через внешний шлюз, кроме 1414; тестовый `MockSmsProvider` позволяет демонстрировать сценарий без фактической отправки.
- Роли специалиста, предпринимателя, руководителя и администратора; аудит действий и системных событий.

## Архитектура и границы ответственности

- **API и сервис уведомлений** проверяют входные данные, создают уведомления и координируют доставку.
- **Демо-провайдер кабинета бизнеса** имитирует передачу уведомления и получение статусов доставки и прочтения.
- **SMS-провайдер** изолирует API конкретного внешнего шлюза. Замена шлюза не должна требовать изменения логики уведомлений.
- **Аудит** фиксирует, кто, когда и какое действие выполнил. Он нужен для истории и разбора событий; сам по себе не сверяет целостность файлов.
- **Проверка целостности** — отдельная функция: хэш файла пересчитывается и сравнивается с сохранённым SHA-256. В MVP её можно добавить вместе с манифестом пакета.

## Технологический стек

- Python, FastAPI, Pydantic
- PostgreSQL, SQLAlchemy, Alembic
- Внешний SMS-шлюз через адаптер `SmsProvider`
- Демо-адаптер кабинета бизнеса через `DeliveryProvider`

## Переменные конфигурации SMS

Секреты и настройки реального шлюза хранятся вне исходного кода, например в `.env` (сам файл не коммитится):

```env
SMS_PROVIDER=mock
SMS_GATEWAY_BASE_URL=
SMS_GATEWAY_API_KEY=
SMS_SENDER=
```

Для реальной отправки значение `SMS_PROVIDER` выбирает адаптер подключённого внешнего шлюза. `mock` используется для локального демо и не отправляет сообщения. 1414 не является провайдером MVP.

## Возможное развитие после MVP

- Подписание ЭЦП через NCALayer и серверная проверка подписи.

- Подключение реального кабинета бизнеса, если соответствующий официальный интерфейс будет доступен.
